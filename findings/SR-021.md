# SR-021 — Public HTML cache policy requires performance review
A13/A17. Proposed priority Medium investigation. Verified header value; measured causal impact unverified. Open.
Source: user-supplied audit.json, SHA-256 f1ce16437a0a19dc260d0859814c17716f7f29673c74e36378cbf5f1ad0a137a reverified; source collector code confirms explicit header allowlist. Crawl 2026-11-27 14:08 IST; deduplicate 31 final HTML records with canonical=[final_url]. Snapshot, not fresh live security testing. No site modifications or intrusive tests.
All 31 captured final canonical HTML responses report Cache-Control: no-cache, no-store, must-revalidate. no-store instructs HTTP caches not to store the response. no-cache otherwise requires revalidation before reuse. This does not prove lack of origin-side page/object caching, CDN caching behavior for other resources, or static asset caching; actual cache hit rate and TTFB unknown. Privacy and dynamic form behavior may justify restrictive caching. Homepage lab workload previously measured B01-F01; no new causal performance claim. Ask for cache strategy by public HTML, static resources, authenticated pages, dynamic forms; show cache headers and hit/miss metrics, repeat navigation and safe invalidation. Closure: assess public vs sensitive responses, preserve privacy and functional form behavior, approve only evidence-based caching changes and retest.
