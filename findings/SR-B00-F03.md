# SR-B00-F03 — Native semantic page landmarks absent

Workstream: Phase 00 / A14 and A06. Observed 2026-11-27 14:08 IST. Priority: Medium (proposed). Evidence: verified native element counts, accessibility impact pending. Review status: Open.

## Standard and interpretation
W3C WAI guidance: https://www.w3.org/WAI/tutorials/page-structure/regions/ ; https://www.w3.org/WAI/WCAG22/Techniques/html/H101 ; https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/ .
Native semantic elements in appropriate contexts or equivalent ARIA landmark roles can expose page regions to assistive technologies. The collector does not record ARIA roles, accessible names, tree scope, visibility or rendered accessibility tree. Absence of native tags alone is not a WCAG conformance failure, nor proof of search ranking or AI citation loss. Potential effects are weaker content separation, harder landmark navigation and maintenance complexity; shared template origin is a hypothesis.

## Reproduction
On homepage and representative programme pages, inspect View Page Source for actual element tags, then run a read-only developer console query:
```js
console.table([...document.querySelectorAll('main,header,footer,nav,[role="main"],[role="banner"],[role="contentinfo"],[role="navigation"]')].map(el=>({tag:el.tagName,role:el.getAttribute('role'),label:el.getAttribute('aria-label')})));
```
Inspect actual browser accessibility tree for banner, main, contentinfo, navigation, accessible names, duplicate/hidden responsive navigation and bypass mechanisms. DOM query alone cannot verify landmark exposure.
